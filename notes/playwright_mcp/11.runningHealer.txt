11 Running the Healer
----------------------
The Healer diagnoses failing tests and fixes them without weakening the assertions.

Step 1 — Break a passing test
-------------------------------------
Open src/pages/LoginPage.ts and introduce a locator error:

typescript    src/pages/LoginPage.ts

// Original — this works
readonly usernameInput = this.page.getByRole('textbox', { name: 'Username' });

// Broken — introduces a typo
readonly usernameInput = this.page.getByRole('textbox', { name: 'User Name' });

Save the file.

Step 2 — Confirm the test fails
-------------------------------------
Terminal
    npx playwright test tests/auth/standard-login.spec.ts

You should see a timeout error waiting for the locator.

Step 3 — Run the Healer
-------------------------------------
1. Switch the chat mode to playwright-test-healer
2. Attach the failing test file to the chat (type # and select the file, or drag it in)
3. Use this prompt:
prompt  in Copilot Chat — Healer mode

The test at #tests/auth/standard-login.spec.ts is failing.

Diagnose and fix following your rules:
    1. Run the test to reproduce the failure
    2. Read the error output carefully
    3. Open the app in a live browser to inspect the actual DOM
    4. Determine root cause
    5. Apply the minimum-viable fix
    6. Preserve assertion intent — do NOT weaken any assertion
    7. Do NOT add waitForTimeout
    8. Do NOT skip the test
    9. Re-run twice to confirm stability
    10. Produce a final report explaining what you did and why

Step 4 — Review the fix
-------------------------
The Healer will produce a diff and a report. Before accepting the fix, verify:
    - Only the broken locator was changed, nothing else
    - No assertions were softened (toHaveCount(6) did not become toBeVisible())
    - No waitForTimeout was added
    - No test was skipped or marked fixme
    - The test passes twice in a row
If any of these fail, reject the fix. Fix it by hand instead.
